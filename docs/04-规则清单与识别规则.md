> 版本 v1.0 ｜ 本文件是 Phase 1 规则实现的**唯一权威来源**
> 关联文档：`03-技术架构`（代码怎么组织）｜ 商业定位 / 路线图 / GTM 属内部战略文档，保存在独立私有仓库。
> 本文件回答：**每一步识别/过滤/索引的"判定条件"到底是什么**。

---

## 0. 规则如何串进流水线

```
config 嗅探 → 决定加载哪些 .scm（Part B/C 的识别规则）
    ↓
ast 用 .scm 提取 EntryNode / CallNode / DBOp（Part B + C）
    ↓
index 按规范建三张索引（Part D + E）
    ↓
engine 按 Funnel 规则过滤定级（Part A + G）
    ↓
llm 仅对 L1 命中 + L2 加权后的链路做 L3 定性（Part A.4 + F）
```

**设计原则**：L0/L1/L2 全部确定性、可单测、不依赖网络；L3 才引入 LLM，且只吃"已命中高危"的输入。

# Part A — 漏斗过滤规则（Funnel Filtering）

## A.1 L0：物理过滤（不解析、不索引）

目标：把非业务逻辑代码挡在门外，降低误报与耗时。

### 跳过清单（黑名单）
| 类型 | Go | Java | 通用 |
|---|---|---|---|
| 测试 | `*_test.go`、`_test/` | `*Test.java`、`src/test/` | — |
| 依赖目录 | `vendor/` | — | `node_modules/` |
| 生成代码 | `*.pb.go`、`*.gen.go`、`mock_*.go` | `*Generated.java`、Lombok/MapStruct 产物、MyBatis 生成器产物 | `docs/`、`.git/` |

### 解析清单（白名单）
- Go：非测试、非 vendor、非 generated 的 `.go`
- Java：`src/main/java/**` + `src/main/resources/**/mapper/**/*.xml`（MyBatis XML 是 SQL 来源）

### 判定函数签名
```go
func shouldParse(path string) bool   // 返回 false 即 L0 过滤
```

## A.2 L1：本地 AST 高危规则（命中即标记高危）

> 规则编号 R1–R7。每条对应 `DBOp` 的一个或多个上下文字段。

### R1 循环内查库（Loop Query / N+1）
- **触发**：`DBOp.InLoop == true` 且 `Op ∈ {Read}`（循环体内出现 DB 读）
- **Go 示例**：
  ```go
  for _, u := range users {
      db.Where("id = ?", u.ID).First(&order)   // ← N+1
  }
  ```
- **Java 示例**：
  ```java
  for (User u : users) {
      orderMapper.selectByUserId(u.getId());    // ← N+1
  }
  ```
- **默认等级**：S2；若循环内无分页/limit 或结果集可能很大 → 升 S1

### R2 循环内写库（Write in Loop）
- **触发**：`DBOp.InLoop == true` 且 `Op ∈ {Write, Delete}`
- **默认等级**：S1（比读更危险，可能产生大量写放大/锁竞争）

### R3 事务内远程调用（Remote Call in TX）
- **触发**：`DBOp.InTx == true` 且同事务区间内存在 `CallKind ∈ {HTTP, GRPC, MQ, ThirdParty}`
- **Go 示例**：
  ```go
  db.Transaction(func(tx *gorm.DB) error {
      tx.Save(&order)
      http.Post(notifyURL, ...)   // ← 长事务 + 外部依赖
      return nil
  })
  ```
- **Java 示例**：`@Transactional` 方法内调用 `restTemplate.postForObject(...)` / Feign / MQ 发送
- **默认等级**：S1；事务内多次远程调用 → S0

### R4 持锁远程调用（Remote Call Under Lock）
- **触发**：`DBOp.UnderLock == true` 且锁区间内存在远程调用
- **Go**：`mutex.Lock()` 到 `mutex.Unlock()` 之间有网络调用
- **Java**：`synchronized` / `ReentrantLock.lock()` / Redisson `getLock` 区间内远程调用
- **默认等级**：S1；锁粒度大（锁住整个方法/对象）→ S0

### R5 无 WHERE 的写操作（Full-table Write）
- **触发**：`DBOp.Op ∈ {Write, Delete}` 且 `Where == ""`（或 SQL 无 where 子句）
- **Go**：`db.Model(&Order{}).Update("status", 1)` 无 `.Where`
- **Java**：MyBatis `<update id="xxx"> UPDATE orders SET ...` 无 `<where>`/where 子句
- **默认等级**：**S0（致命，阻断合并）**

### R6 忽略错误的写操作（Write Without Error Check）
- **触发**：`DBOp.Op ∈ {Write, Delete}` 且返回的 error/受影响行数未被检查
- **Go**：`db.Save(&x)` 返回值未赋值/未判断
- **Java**：`mapper.update(...)` 返回值（int）未判断
- **默认等级**：S2（可选规则，可配置开关）

### R7 无超时的远程调用（Remote Call Without Timeout）
- **触发**：`CallKind ∈ {HTTP, GRPC}` 且无 `context.WithTimeout` / `http.Client{Timeout}` / `@HystrixCommand` / RPC timeout 配置
- **Go**：`http.Get(url)` 无 context；`grpc.Dial` 无 timeout
- **Java**：`restTemplate` 无超时；Feign 未配 timeout
- **默认等级**：S2

---

## A.3 L2：复杂度与注释校验（不直接告警，作 L3 权重）

- **圈复杂度**：Go 用 AST 计分支（if/for/switch/case），Java 同；阈值 > 15 标记
- **大函数**：行数 > 80
- **关键路径注释缺失**：被 L1 命中的函数，若缺少函数级注释 → 权重 +1
- **作用**：只作为"是否值得花 LLM 成本做 L3"的排序依据，**不单独产生告警**

---

## A.4 L3：LLM 深度定性（仅高危链路进入）

- **触发条件**：`L1 命中` 且 `L2 加权后 score ≥ 阈值`（默认阈值可配）
- **输入**：命中链路的 `[]CallNode`（含调用位置）+ 业务标签（Part F）+ 近似 SQL
- **输出**：`RiskReport{ Level, Summary, Suggestion }`
- **Prompt 模板骨架**：
  ```
  你是资深后端架构师。以下是一条从入口到下游的调用链，已由静态分析标记为高危（原因：{R编号}）。
  请判断：1) 实际风险等级 2) 对业务的具体影响 3) 修复建议。
  链路：{call chain}
  业务上下文：{tags}
  只基于给定信息，不确定的地方明确说"无法确定"。
  ```
- **约束**：L3 只做**定性**，绝不参与依赖提取（依赖提取必须确定性，杜绝幻觉）。

# Part B — 入口识别规则（Entry Detection）

> 入口 = 系统对外暴露或被动触发的执行起点。提取产物统一为 `EntryNode`。

## 入口 ID 命名规范（稳定、可读、可排序）
```
http:{METHOD}:{path}           # http:GET:/api/v1/orders
grpc:{Service}.{Method}        # grpc:OrderService.GetOrder
kafka:{topic}                  # kafka:order-created（group 放 PodHints）
xxl:{jobHandlerName}           # xxl:orderDailyJob
```

## B.1 HTTP 入口

### Gin（Go）
- **识别点**：`r.GET/POST/PUT/DELETE/PATCH/Any` 注册；`r.Group("/prefix")` 拼前缀
- **提取**：method、path（含 group 前缀）、handler 函数、`file:line`
- **示意 .scm（需按 go grammar 校准节点名）**：
  ```scheme
  ; r.GET("/path", handler)
  (call_expression
    function: (selector_expression
      operand: (identifier) @receiver
      field: (field_identifier) @method
      (#match? @method "^(GET|POST|PUT|DELETE|PATCH|Any)$"))
    arguments: (argument_list
      (interpreted_string_literal) @path
      (identifier) @handler)) @entry
  ```

### Spring MVC（Java）
- **识别点**：`@RestController` / `@Controller` 类 + `@RequestMapping` / `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` 方法
- **提取**：类级路径 + 方法级路径拼接、HTTP method、handler 方法
- **示意 .scm**：
  ```scheme
  ; 类上的 @RestController + @RequestMapping
  (class_declaration
    (modifiers (annotation name: (identifier) @anno (#match? @anno "RestController|Controller")))
    body: (class_body)) @class
  (method_declaration
    (modifiers (annotation name: (identifier) @m (#match? @m "RequestMapping|GetMapping|PostMapping|PutMapping|DeleteMapping")))
    name: (identifier) @handler) @entry
  ```

## B.2 gRPC Server 入口

### grpc-go
- **识别点**：`pb.RegisterXxxServer(grpcServer, &impl{})` → 找到 `impl` 类型的所有方法
- **提取**：Service（Xxx）、Method（impl 方法名）、handler、位置

### grpc-java
- **识别点**：`class XxxImpl extends XxxGrpc.XxxImplBase` + `@Override` 方法
- **提取**：Service、Method、handler

## B.3 Kafka Consumer 入口

### Go（sarama / confluent-kafka-go）
- **识别点**：`consumer.ConsumeClaim/ConsumePartition`、`ConsumerGroup.Consume` 的实现方法；`Subscribe(topics...)` 提取 topic
- **提取**：topic、group、handler

### Java（Spring Kafka）
- **识别点**：`@KafkaListener(topics = "order-created", groupId = "x")` 方法
- **提取**：topic、groupId、handler

## B.4 XXL-Job 入口（中国栈关键）

### Java
- **识别点**：`@XxlJob("orderDailyJob")` 标注的方法
- **提取**：jobHandlerName、handler 方法、位置
- **价值**：这是西方工具完全不会识别的入口类型，**是核心差异化之一**

# Part C — 调用链与下游操作识别

## C.1 调用类型分类（CallKind）
| Kind | 含义 | 识别特征 |
|---|---|---|
| DB | 数据库读写 | GORM / MyBatis / JdbcTemplate（见 C.2） |
| Redis | 缓存/分布式锁 | redis client / redisTemplate |
| Lock | 加锁 | `sync.Mutex` / `synchronized` / Redisson |
| MQ | 消息生产 | producer.Send / KafkaTemplate.send |
| HTTP | 出站 HTTP | `http.Get/Post` / restTemplate / Feign |
| GRPC | 出站 gRPC | client stub 方法调用 |
| ThirdParty | 第三方 SDK | 支付/短信/云 SDK 调用 |
| Func | 普通函数 | 其余函数调用（用于构建调用链） |

## C.2 DB 操作识别（下游操作分析核心）

### GORM（Go）
- **读方法**：`Find` `First` `Take` `Where`(→Find) `Select` `Count` `Pluck` `Scan` `Raw`(SELECT)
- **写方法**：`Create` `Update` `Delete` `Save` `Exec` `Raw`(INSERT/UPDATE/DELETE)
- **表名提取**（优先级从高到低）：
  1. `db.Table("orders")` 字面量
  2. `db.Model(&Order{})` → 从 struct 类型名推断（`Order` → `orders`，支持复数规则 + `gorm:"table:xxx"` tag）
  3. `db.Raw("... FROM orders ...")` → 解析 SQL
- **字段/WHERE 提取**：`Where("id = ?", v)` 字面量、`Select("col1,col2")`、链式条件拼接近似 SQL

### MyBatis（Java）
- **Mapper 方法 → XML 映射**：`OrderMapper.selectByUserId()` → `OrderMapper.xml` 里 `<select id="selectByUserId">`
- **表名/字段/WHERE**：解析 XML 内 SQL（select/insert/update/delete 标签）
- **读写判定**：`<select>` = Read，`<insert>/<update>/<delete>` = Write

### Spring JdbcTemplate（Java）
- **识别点**：`jdbcTemplate.query/queryForObject/update/execute`
- **表名/WHERE**：从 SQL 字符串字面量解析

## C.3 Redis / 缓存
- **Go**：`redis.Get/Set/HGet/HSet/...`，key 从第一个参数字面量或格式化串提取（`cache:user:%d`）
- **Java**：`redisTemplate.opsForValue().get(key)`、`@Cacheable(cacheNames=...)`
- **产出**：`ResourceKey{Kind:"key", Name:"cache:user:..."}`

## C.4 锁
- **Go**：`sync.Mutex.Lock()`（注意区分 mutex 实例）；分布式锁 `SetNX`/redlock
- **Java**：`synchronized` 块、`ReentrantLock.lock()`、Redisson `getLock(key)`

## C.5 MQ 生产
- **Go**：`producer.Send/Produce(msg)`，topic 从配置或字面量提取
- **Java**：`kafkaTemplate.send("topic", ...)`、`rocketMQTemplate.convertAndSend`

## C.6 上下文识别（填充 DBOp 四个布尔字段）

| 字段 | 判定方法（AST 祖先链） |
|---|---|
| `InLoop` | 调用点祖先链含 `for`/`range`/`while` 节点 |
| `InTx` | Go：`db.Transaction(func(tx){...})` 闭包内；Java：`@Transactional` 方法内 或 `TransactionTemplate` |
| `UnderLock` | 祖先链处于 `Lock()` 到 `Unlock()` 区间（Go）/ `synchronized` 或 `lock()` 块（Java） |
| `InGoroutine` | Go：`go func(){...}` 内；Java：`new Thread`/`CompletableFuture.runAsync`/线程池提交 |

# Part D — 反查索引规则（Reverse Index）

> 目标：回答"改这个资源会波及哪些入口"。

## 资源 key 规范
| Kind | key 格式 | 示例 | 来源 |
|---|---|---|---|
| table | `table:{name}` | `table:orders` | C.2 表名提取 |
| key | `key:{pattern}` | `key:cache:user:{id}` | C.3 |
| config | `config:{key}` | `config:db.max_open` | 配置读取点 |
| method | `method:{Service.Method}` | `method:UserService.GetUser` | 公共方法/被调用方 |
| topic | `topic:{name}` | `topic:order-created` | MQ 生产/消费 |

## 提取规则
- **配置 key**：
  - Go：`viper.Get("db.max_open")` / `viper.GetString("...")` 的字面量
  - Java：`@Value("${db.max_open}")`、Apollo `@ApolloConfig`/`ConfigService.getConfig`、Nacos `@NacosValue`
- **公共方法**：被多个入口调用的、非入口的函数（在正向索引中 `CallKind=Func` 且被调次数 ≥ 2）自动进反查索引
- **读写区分**：`Ref.Op ∈ {Read, Write}` 必须带上，支持"按数据库读写区分"查询

# Part E — 排查索引规则（Trouble Index）

> 目标：回答"这个报错/超时/日志从哪返回，下一步查哪"。

| 索引维度 | key 格式 | 识别特征 | 提取值 |
|---|---|---|---|
| 错误码 | `err:{code}` | Go `errors.New("10001: ...")`/`fmt.Errorf`；Java `throw new BizException("10001", ...)`、`ResultCode` | code + 位置 |
| 错误返回点 | `errret:{func}` | `return err` / `throw` 位置 | file:line |
| 日志模板 | `log:{literal}` | `log.Error("...")` / `log.error("...")` 的字符串模板 | 模板字面量 + 位置 |
| 超时 | `timeout:{loc}` | `context.WithTimeout`、`http.Client{Timeout}`、`@HystrixCommand(timeout)`、RPC timeout | 超时值 + 位置 |
| 枚举 | `enum:{name}` | Java `enum` 定义 + 字段注释；Go `iota` 常量组 | 枚举值 + 注释 |

# Part F — 业务元数据关联规则（Phase 2，接口预留）

> 目标：从外部系统补全"这个接口/表是做什么业务的"。Phase 1 只定义 `MetadataSource` 接口，实现留到 P2。

| 元数据源 | 匹配键 | 补全内容 | Confidence |
|---|---|---|---|
| YApi | `http:{method}:{path}` | 接口标题、说明、参数/返回值 | 高（精确匹配） |
| proto 注释 | `grpc:{Service}.{Method}` | method 上方 `//` 注释 | 高 |
| TiDB 表结构 | `table:{name}` | 表注释、列注释（`information_schema` 的 TableComment/ColumnComment） | 高 |
| XXL 管理端 | `xxl:{jobHandlerName}` | 任务描述、调度参数 | 中 |

- **产出**：`BusinessTag{ Kind, Value, Confidence }`
- **L3 使用**：对证据充分（Confidence 高）的表/方法，生成"可能的业务影响摘要"；证据不足则明确"无法确定"，不硬编

# Part G — 风险等级定义

| 等级 | 含义 | 默认动作 |
|---|---|---|
| **S0 致命** | 可能导致全表更新/数据丢失/长时间阻塞 | 阻断合并，强制人工确认 |
| **S1 高危** | 明确性能/稳定性隐患 | 需人工确认后才能合并 |
| **S2 中危** | 潜在风险，建议优化 | 提示，不阻断 |
| **S3 低危** | 建议性 | 可选展示 |

## 判定矩阵（规则 × 条件 → 等级）

| 规则 | 基础条件 | 默认等级 | 升级到 | 升级条件 |
|---|---|---|---|---|
| R5 无 WHERE 写 | write && no where | **S0** | — | — |
| R2 循环内写库 | InLoop && Write | **S1** | S0 | 写放大明显/无批量 |
| R3 事务内远程调用 | InTx && remote | S1 | S0 | 事务内 ≥2 次远程 |
| R4 持锁远程调用 | UnderLock && remote | S1 | S0 | 锁粒度大 |
| R1 循环内查库 | InLoop && Read | S2 | S1 | 无分页/结果集大 |
| R7 无超时远程 | remote && no timeout | S2 | — | — |
| R6 忽略错误写 | Write && no err check | S2 | — | — |

# Part H — 规则质量与回归测试

> 规则是本产品"确定性护城河"的地基，**准确率决定生死**。

## 测试集构建
1. 选取 **3+ 真实微服务仓库**（至少 1 Go + 2 Java，覆盖 Spring Boot + MyBatis + Dubbo + XXL）
2. 人工标注 golden cases：已知入口、已知调用链、已知高危点
3. 每个 R 规则至少 5 个正例 + 5 个反例

## 质量指标
| 指标 | 定义 | Phase 1 目标 |
|---|---|---|
| 入口识别准确率 | 正确识别入口 / 全部入口 | ≥ 95% |
| 调用链召回率 | 追到的真实调用 / 全部调用 | ≥ 90% |
| DBOp 字段准确率 | 表名/key/WHERE/上下文布尔 正确 | ≥ 90% |
| 高危误报率 | 误报 / 全部告警 | ≤ 15% |

## 回归纪律
- 每次 `.scm` 或识别规则改动 → 必须跑 golden 测试集
- 误报/漏报案例**回灌**进测试集（测试集随产品增长）
- 规则改动需在 `docs/04` 同步更新（本文档即规则 truth）
